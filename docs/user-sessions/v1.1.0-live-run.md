PROVENANCE: the release agent acted as the user AND the orchestrator, following `README.md` and
`skills/strictlybetter/SKILL.md` (then orient, metrics, run) verbatim, against a fresh
`make_fixture.py pyfix` copy, with the plugin installed from the local marketplace into
`~/.claude/plugins/cache/strictlybetter/strictlybetter/1.1.0`. Every engine command ran from that
cache. What this certifies: the flow from empty repo to an accepted commit with provenance, the
blind chain (payload → judge → verdict → paired confirm), the discard paths (noise, invalid), the
distiller, `campaign end`, the report, and the external re-validation. What it cannot certify: the
plugin's registered agent types and hooks firing inside a live Claude Code session (the plugin was
installed mid-session, so `strictlybetter:sb-*` agents were unavailable and the PreToolUse/Stop
hooks were not loaded; general agents read the agent files and followed them; hooks were exercised
from the shell in `tests/test_hooks.py`). Not a real maintainer's repo, not an overnight run.

WHAT WORKED
- Orient: profile correct (python-package 0.95; test and bench verified by running them).
- Metrics: 10 cards from one metrologist call, all 6 goal/guardrail probes monotonic, baseline in 57 s.
- Gate 1 rendered the measured facts (sigma 22.7 ms on 481 ms, MDE 8.6%) and asked exactly one question.
- e0001 (pairs_with_sum count map): screen 68.6→20.1 ms, judge clean, paired confirm 271.0→127.7 ms
  on holdout seeds against a fresh head, accepted, provenance block in the commit. External
  re-validation (`bench --mode analyze`): genuine, process wall 1.003→0.489 s, outputs match, tests pass.
- e0002 (thread pool, the bandit's `concurrency` pick): retry-screen then discard as noise (+3.1 ms
  on a 6.8 ms threshold), diff archived, cost recorded. The archive hint reached e0003's task file.
- Distiller wrote an 8-section inheritance body that correctly refused to credit diagnostic movement.
- `campaign end` produced a report whose guardrail column is computed from recorded start values.

WHAT CONFUSED ME
- `status --json` said `"profile": true` on a fresh repo (a hardening side effect from today); the
  front door would have skipped orient. I followed the truth on disk. FIXED in 1.1.1.
- The bandit proposed `concurrency` for a single-threaded pure-Python microbench and the run skill
  gives the orchestrator no way to decline an operator. It cost one experiment. OPEN: the skill
  should let the orchestrator swap an operator with a stated reason, logged.
- The brief's diagnostic values were stale after the accept (pairs_with_sum_ms still 225.751 while
  bench_ms had moved). FIXED in 1.1.1 (diagnostics refresh from the confirm run on accept).

WHAT I WOULD HAVE QUIT OVER
- e0003, the genuine `word_freq` fix (screen 20.1→4.9 ms, judge clean), was discarded as `invalid`
  at full fidelity because the whole bench finished in 0.178 s, below the card's
  `expected_duration_s` lower bound of 0.3 s. The metrologist set the band around the baseline's
  duration; a real 25× win legitimately falls below it. The card is frozen for the campaign, so the
  last budget slot would fail the same way; I ended the campaign. FIXED in 1.1.1 at the guidance
  level (lower bound = the instrument's fixed cost with the work stubbed, never a fraction of the
  baseline) and the timer-divergence check was rewritten to absolute savings so fixed overhead
  cannot trip it either.
